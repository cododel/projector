## Problem And Impact

Для solo-agent разработки оператору нужен единый обозреваемый каталог компонентов
и полного набора состояний интерфейса, позволяющий контролировать дизайн без
отдельного дизайнера. Пока доступна только раскадровка уведомлений; она не является
полным каталогом приложения. Storybook в проект не установлен.

## Evidence And Current Boundary

- `dev/notifications-storyboard.tsx` использует реальные NotificationStack и controller;
  `pnpm storyboard:notifications` собирает автономную страницу с девятью состояниями
  и интерактивными переходами.
- Оператор сначала поручил внедрить общие уведомления. Storybook согласован как
  отдельный будущий этап; при closeout оператор напомнил «и про storybook не забудь».
- Каталог должен показывать реальные компоненты и их состояния, а не независимые
  HTML-макеты, способные разойтись с приложением.

## Why Deferred

Текущий этап завершает уведомления и предшествующие изменения сессий. Полный каталог
затрагивает другие панели, модальные окна и настройки; он сохраняется отдельной
возобновляемой задачей. Наличие этой записи не означает, что Storybook уже внедрён.

## Resume Conditions And First Actions

1. Начать по отдельному поручению на внедрение каталога.
2. Составить инвентарь реальных компонентов и состояний по renderer, PRD и существующим
   тестам. Отделить локальные UI-состояния от native Electron и runtime-интеграций.
3. Проверить актуальную совместимость Storybook с установленными React/Vite/TypeScript;
   определить способ изоляции bridge и подключения production CSS без личных данных.
4. Перенести notification storyboard в stories, затем расширять каталог по инвентарю.
   Правила полноты и визуальные проверки определить до объявления каталога полным.

## Completion Criteria

- [ ] Единая локальная команда запуска и статической сборки каталога документирована.
- [ ] Навигация показывает компоненты, составные интерфейсы и карту их состояний.
- [ ] Состояния используют production-компоненты, стили и детерминированные данные.
- [ ] Для каждого включённого компонента перечислены применимые normal, hover, focus,
      selected, disabled, pending, empty, success/warning/error и длинное содержимое;
      неподдерживаемые варианты явно отмечены, покрытие не заявлено без инвентаря.
- [ ] Можно просматривать переходы, keyboard и reduced motion, фиксировать визуальные
      регрессии; native-only поведение имеет отдельную границу проверки.
- [ ] Каталог не пишет реальные session/project/profile данные и не запускает реальные
      Archive/Undo, процессы или модельные операции.
- [ ] Документация позволяет агенту находить и обновлять состояния при изменении UI.
