# Blueprint Alpha 1

Версия приложения и руководства: `0.1.0-alpha.1`. Версии проекта, опубликованного документа, сохранённого состояния и SDK проверяются отдельно; версия руководства не доказывает совместимость форматов. Документ фиксирует текущий объём реализации, а PRD — целевой продукт и отдельно обозначенные следующие этапы.

## Основной цикл

Агент создаёт артефакт с `originSession` → пишет MDX и публикует документ → оператор отвечает и аннотирует → **Save** фиксирует состояние → оператор вручную переносит **Copy update message** в связанную сессию → агент читает снимок и публикует новую версию. Утверждение отдельно фиксирует согласование конкретной версии и состояния; оно не отправляет сообщение, не разрешает реализацию и не обновляет контракты автоматически.

## Хранение и совместимость

Неизменяемая версия документа, приватное рабочее состояние и неизменяемый сохранённый снимок — разные сущности. В проектной `.blueprint` хранятся исходники, опубликованные ревизии, saved states с вложениями, legacy Submit-пакеты и утверждения. В данных приложения — значения, комментарии, черновые изображения, незавершённый поповер и индексы. Рабочие данные привязаны к артефакту. Два артефакта одного проекта для разных сессий не смешивают ответы или комментарии.

Save дожидается подтверждённого автосохранения. Незаконченный комментарий нужно сохранить либо отменить. Запись использует staging и атомарную фиксацию; незавершённый снимок после сбоя не становится доступным. Одинаковый `operationId` возвращает прежний результат; иное содержимое операции либо несовпадение ожидаемого последнего сохранённого состояния даёт конфликт. Исторический снимок не меняется при редактировании или удалении комментария в текущей работе. Save фиксирует все аннотации, включая ссылки на прежние версии, и не очищает их.

Совместимые ответы переносятся только при совпадении ID, типа/схемы, смысла и версии семантики. Остальные остаются при исходной ревизии. Аннотации не перепривязываются автоматически, утверждение не переносится. Старые приватные проектные черновики мигрируют к соответствующим артефактам без публикации и потери данных. Legacy Submit-пакеты и утверждения сохраняются читаемыми; никакой миграцией черновик не превращается в saved state.

Документ разбирается в сериализуемое проверенное дерево; исходный MDX не исполняется. Imports, JavaScript, event handlers и неизвестные компоненты отклоняются. Mermaid рендерится в strict-режиме. Исходный текст изменяет агент. Виджет не получает Save, Approve, shell, файловые или MCP-привилегии.

## Аннотации и браузер

После фиксации комментария снимок показывается без поля и текста комментария поверх него: только исходный замороженный viewport, рамка и указатель с номером. Комментарий остаётся в сайдбаре и JSON; поле открывается только для редактирования. Ошибка записи не закрывает редактор. Save фиксирует нумерацию вложения вместе с состоянием; изменения страницы во время ввода не меняют исходный viewport.

Слева — единое дерево раскрываемых папок проектов с однострочными планами, сокращением длинного заголовка и подсказкой. Иконка показывает Draft, In review или Approved; приватные изменения обозначаются отдельно. Кнопка Codex открывает сохранённый `codex://threads/{originSession.sessionId}` без выбора плана и проверки доступности сессии. Закреплённая вторая панель непосредственно под вкладками содержит название, выбор **Version N** и статус; в документе там же расположены Annotate и состояние приватного сохранения. Прокрутка документа не уводит панель с экрана. Большой шапки и VISUAL PLANNING нет. Общая компактная панель окна сохраняет нативные кнопки macOS и область перетаскивания. Переключатель проектов расположен рядом с нативными кнопками, переключатель обратной связи — у правого края. Оба доступны при скрытых сайдбарах и на стартовом экране; кнопки исключены из области перетаскивания. Они скрывают и возвращают соответствующий сайдбар; видимость сохраняется локально, область браузера корректно меняет размеры. Технические UUID не показываются в обычных карточках.

Уведомления обновления объединяются в один цикл чтения. События во время чтения, перехода или приватного автосохранения остаются ожидающими и учитываются следующим проходом; устаревшая поверхность не читает документ другой версии или плана. Список получает статусы без компиляции предпросмотра каждого плана. Повторные чтения реестра и состояния объединяются только внутри одной операции, без долгоживущего кэша файлов.

Создание комментария начинается с одной строки и небольших действий рядом. Поле растёт по переносам и обёртке длинного текста до шести текстовых строк плюс отступы, затем прокручивается внутри. Enter фиксирует приватный комментарий, Shift+Enter добавляет строку, Escape отменяет; IME не отправляет комментарий преждевременно. Клик снаружи фиксирует непустой текст, пустой новый комментарий отменяет, пустое редактирование отменяет с сохранением прежнего комментария. В режиме редактирования доступны Delete, Cancel и Save; их нажатия не считаются кликом снаружи. Правила одинаковы для документа, карточки и доверенной браузерной поверхности; клик по замороженному снимку не передаётся сайту. Фиксация комментария не заменяет Save артефакта. Аннотация содержит номер, краткую цитату/описание и комментарий, доступные иконки edit/delete. Клик раскрывает свёрнутые разделы, показывает исходную версию и подсвечивает точный диапазон. Повторяющиеся цитаты различаются по диапазонам; пересекающиеся аннотации сохраняют разные номера.

Сохранённое агентское представление содержит `text`, `annotation`, `source`, внутренний ID и тип привязки. `source` указывает артефакт, ревизию, диапазон либо снимок. Документные аннотации дополнительно содержат `stateContext={stateHash,values,view:{details}}`. SHA-256 связывает канонические значения виджетов и открытые/закрытые Details с артефактом и ревизией в момент создания аннотации. Это исходный контекст замечания, а не согласие или новая версия рабочих ответов. Порядок массива задаёт номера одновременно для карточек, inline-пометок и изображений. Номера фиксированы для данного saved state; сопоставление разных состояний использует внутренние ID.

Каждый план имеет собственные вкладки `document | home | browser`, порядок и выбранную версию. Плюс создаёт New tab с фокусом в поле URL; адрес превращает эту же вкладку в браузерную. Адресная строка, Back, Forward и Reload появляются только в браузере; его Annotate расположен в браузерной панели, а документный — в закреплённой панели плана. Документ открывается или переиспользуется при выборе плана; остальные вкладки сохраняются при переходе к другому плану. После закрытия последней вкладки остаются Open plan и New tab. Черновик объясняет, что браузер требует опубликованной версии.

Переключение плана/вкладки и закрытие сначала завершают комментарий и ждут локальной записи. При ошибке ввод остаётся доступным, переход блокируется. Крестик и middle-click используют одну последовательность закрытия: приватная работа Blueprint сохраняется без Save и публикации; план не удаляется. Ошибка записи предлагает Retry/Cancel. Сигнал сайта `beforeunload` отдельно требует Close tab/Cancel с отменой по умолчанию; вкладка удаляется из реестра после уничтожения webContents. Повторный dispose, уже уничтоженная страница и поздний результат capture обрабатываются безопасно.

Метаданные вкладок и видимость сайдбаров хранятся в данных приложения, без изменения форматов документов и saved states. После перезапуска браузеры восстанавливаются лениво по URL; содержимое формы сайта и полная история не гарантируются. Исходные снимки аннотаций сохраняются.

Браузерная вкладка принадлежит артефакту и открывается оператором либо через `show_content({artifactId,url})`. Внешняя страница отделена от доверенной оболочки и не получает Node, файловую систему или операторские команды. Только HTTP/HTTPS, включая localhost; привилегированные схемы запрещены. Проектные профили не разделяют cookies и web storage.

Annotate area выполняется доверенной поверхностью над страницей. Комментарий относится к зафиксированному полному viewport вкладки с прямоугольником, масштабом, прокруткой; для браузера также URL, заголовком и временем. Сохранённое изображение содержит рамку и номер. Изменение размера окна/страницы не переписывает привязку. Инструмент рамкой показывает элемент под курсором: клик выбирает элемент, перетаскивание — произвольную область. Номерная пометка указывает точно в место клика при выборе элемента либо в место отпускания левой кнопки после выделения области; исходная точка сохраняется в привязке и отмеченном изображении. Текстовое выделение и Annotate остаются отдельным действием; для текста сохраняются точный диапазон и соседний контекст.

Браузер проверяет выбранный элемент или область, переходы страницы, viewport, масштаб и прокрутку. Динамические изменения вне выбранной области сами по себе не блокируют захват. При изменении содержимого или геометрии выбранной области захват повторяется не более трёх попыток, до создания приватного черновика. Повтор не выбирает другой элемент вместо исходного. Смена страницы, viewport, масштаба или прокрутки отклоняется; непрерывные изменения выбранной области дают подсказку выбрать заново и оставляют инструмент доступным. Это ожидаемый результат инструмента, без отказа IPC-обработчика.

Маркеры документа скрываются при несовпадении значений виджетов либо Details с исходным контекстом. Клик по аннотации другого состояния открывает исходный контекст только для чтения, не меняя приватные ответы; отдельное действие возвращает текущую работу. Для браузера source дополнительно может содержать `pageId`, `stateHash`, `layoutHash`, `elementAnchor`. Идентичность страницы берётся из ключа записи Navigation API Chromium; Electron сообщает о переходах и загрузке. При недоступности ключа привязка после перехода консервативно скрывается. `history.state` сайта не изменяется. При совпадении контекста live-маркеры следуют элементу при scroll, включая sticky и таблицы; при недействительной привязке скрываются. Неизменяемый снимок остаётся авторитетным контекстом. Legacy-аннотации читаются; неоднозначные старые области показываются только на замороженном снимке.

## MCP и приёмка

`read_artifact({artifactId,part:"state",savedStateId?,cursor?})` возвращает конкретный или последний сохранённый снимок с ответами, аннотациями и исходными версиями. Manifest/source читаются отдельными частями; `revisionId` выбирает опубликованную версию. `read_attachment({artifactId,savedStateId,attachmentId,cursor?})` читает только вложение сохранённого состояния. Большие данные выдаются частями с явным cursor. `list_feedback`, `read_feedback` и `report_feedback` сохраняют доступ к legacy пакетам; отчёт агента является заявлением, а не доказательством выполнения.

Обязательная проверка на одноразовых проектах и профилях:

Обычные `pnpm check`, `pnpm test:e2e` и прямой Playwright запускают скрытые нефокусируемые окна Electron с отключённым background throttling. Это тестовый режим, включая dev, production-пакет и отдельные fixtures; обычное приложение сохраняет своё поведение. Аудит нативных событий отклоняет показ или фокус окна и активацию приложения. Явный `pnpm test:e2e:visible` нужен для видимого отладочного прогона. Скрытый режим не заменяет проверки системного фокуса, IME, меню/диалогов и поведения видимости; требуется графическая сессия. Совместимость подтверждается для конкретной ОС и Electron, а не одним наличием режима.

Локальный `pnpm check` выполняет скрытый E2E без активации окон; композиция рабочего стола и нативный ввод этим режимом не подтверждаются. Полный `pnpm check:full` включает статические проверки, unit, скрытую гарантию, все применимые видимые E2E (включая Codex). Pre-push проверяет отправляемые коммиты в отдельной рабочей копии. VM и pre-commit не требуются; полный запуск намеренно использует фокус окна. Подробности — `docs/testing/TESTING.md`.

- Реальный MCP и Electron: два артефакта разных сессий без project binding; ответы/аннотации → Save → чтение снимка и изображения → новая версия.
- Перезапуск сохраняет приватный ввод, но MCP его не выдаёт; Save не очищает комментарии; повтор операции и сбой после фиксации не создают дубль или частичный снимок.
- Пустой/корректный/ошибочный Draft preview; компактное дерево и длинные заголовки; закреплённая панель под вкладками не движется при прокрутке; toggles изменяют viewport и восстанавливают видимость сайдбаров после перезапуска; Annotate по отдельному действию, отмена, редактирование, удаление, IME, одна/шесть/семь строк и внутренний скролл. Клик снаружи, ошибка записи и повторные события не теряют ввод и не создают дубликат.
- Изоляция вкладок двух планов одного проекта и другого проекта; New tab, адресная строка только браузера, middle-click/крестик, последняя вкладка и восстановление по URL. Приватные ответы и комментарии переживают закрытие без Save. beforeunload Cancel/Close, уже уничтоженная страница и повторный cleanup не вызывают исключений.
- Повторяющиеся цитаты, несколько текстовых узлов, пересечения, Details и переход к старой версии; одинаковая нумерация всех представлений снимка. При изменении ответа/Details старый маркер скрыт, read-only исходный контекст не меняет рабочие ответы, возврат восстанавливает текущую работу.
- Hover рамка, выбор элемента кликом и области drag; указатель номера совпадает с исходным кликом/отпусканием мыши, сохранённое изображение содержит полный viewport. Независимые часы или анимация вне выбранной области не блокируют capture; изменение самой выбранной области даёт повтор либо явный отказ. Браузерная history identity не меняет history.state сайта; scroll/sticky/table привязки корректны либо маркер скрыт, frozen capture доступен всегда.
- Области при прокрутке, zoom, изменении окна и навигации; проектные профили изолированы; внешняя страница не выполняет Save и не получает черновики.
- Save, Approve и разрешение реализации независимы; совместимость состояния проверяется сервером независимо от чтения руководства.
- Основной цикл проходит в development и production, `pnpm check` и чтение новым MCP-клиентом. Native folder picker может получать детерминированный ответ; runtime/хранилище не подменяются.

Результаты и совместимость клиентов фиксируются отдельно. Приёмка нового уточнения stateContext и live-маркеров не считается завершённой по одному наличию документации. Прежняя проверка Codex для Submit не доказывает новый saved-state цикл. Наличие требований и зелёных локальных тестов само по себе не подтверждает поддержку всех клиентов или получение инструкции моделью.

## Следующие этапы

Автоматическая доставка/steer, обнаружение и чтение сессий, аннотирование чата и произвольных файлов, TSX-прототипы, захват нескольких случаев и replay не входят в этот этап. ## Определение сборки и подключение MCP

`app.isPackaged` определяет установленную `.app`. В исходниках наличие dev renderer URL отличает `pnpm dev` от production preview; одна лишь production-сборка не превращает исходники в packaged приложение. Пути исходного bridge вычисляются от `app.getAppPath()`, packaged helper — от фактического `process.resourcesPath`. Настройка включает точный socket текущего runtime. В packaged режиме системный Node не ищется, а отсутствующий helper вызывает явную ошибку. Внешний dev renderer URL packaged приложение игнорирует.

`pnpm package:mac` создаёт локальную unsigned `.app` для архитектуры текущего Mac, с macOS Node.js `24.20.0`, лицензией Node и stdio helper. Подпись и нотарификация не выполнены. Перемещение приложения требует повторного копирования конфигурации с новым путём. Уже подключённый bridge не переподключается автоматически после перезапуска runtime.
